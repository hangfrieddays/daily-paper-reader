## 摘要
扩散强化学习（RL）近期在图像与视频生成模型的后训练中取得了显著成功。然而，包括 DanceGRPO 和 FlowGRPO 在内的大多数扩散 RL 方法，都会在 rollout 之后对选定的时间步进行带梯度跟踪的重计算。在 rollout 与更新使用同一后端的同策略训练下，这种重计算在数学上是冗余的。直观上，rollout 与策略更新步骤可以复用同一个前馈骨干网络以避免冗余计算，但这样做会在 rollout 期间带来很大的内存开销。为了解决该问题，我们提出 LeanGRPO，通过重构数据并行布局，并引入两种面向轨迹对数概率（trajectory-logprob）扩散强化学习的免重计算训练调度：（1）LeanGRPO-Retain 在 rollout 期间启用梯度跟踪，并在更新时直接复用由此得到的计算图和保存的激活值进行反向传播，无需重计算；（2）LeanGRPO-Reweight 同样在 rollout 期间启用梯度，但会使用临时优势值立即对每个选定步骤进行反向传播，并延迟梯度同步，然后在轨迹完成后用真实优势值校正临时梯度。这两种调度面向不同的模型规模和输入大小。在 FLUX.1-dev 和 Wan 上的 FlowGRPO/DanceGRPO 中，LeanGRPO 在保持原始优化目标的同时，实现了最高 1.83 倍的端到端加速。

## Abstract
Diffusion reinforcement learning (RL) has recently achieved significant success in post-training image and video generative models. However, most diffusion RL methods, including DanceGRPO and FlowGRPO, recompute selected timesteps with gradient tracking after rollout. Under on-policy training with the same backend for rollout and update, this recomputation is mathematically redundant. Intuitively, the rollout and policy update steps can reuse the same feed-forward backbone to avoid redundant computation, but doing so can incur a large memory overhead during rollout. To address the issue, we present LeanGRPO by restructuring the data-parallel layout and introducing two recompute-free training schedules for trajectory-logprob diffusion RL: (1) LeanGRPO-Retain enables gradient tracking during rollout and directly reuses the resulting computation graphs and saved activations for backward during update, requiring no recomputation; and (2) LeanGRPO-Reweight also enables gradients during rollout, but immediately backpropagates each selected step using a provisional advantage and delays gradient synchronization, then corrects the provisional gradients with the true advantage after the trajectory is completed. These schedules target different model scales and input sizes. Across FlowGRPO/DanceGRPO with FLUX.1-dev and Wan, LeanGRPO achieves up to 1.83x end-to-end speedup while preserving the original optimization objective.

# LeanGRPO 论文总结

## 一、核心问题与整体含义（研究动机与背景）

- **背景**：扩散/流匹配生成模型的强化学习后训练（如 DDPO、DPOK、FlowGRPO、DanceGRPO）已成为对齐图像与视频生成模型的重要手段。这类方法将去噪过程视为一条策略轨迹，通过转移对数概率（trajectory-logprob）优化终端奖励。
- **核心痛点**：主流实现采用"两阶段"执行——先无梯度 rollout 采样轨迹并计算奖励/组内优势，随后在更新阶段**对选定时间步重新前向计算**（recompute）以重建可微路径用于反向传播。
- **关键洞察**：在**同策略（on-policy）、单次更新、rollout 与 update 使用同一后端**的设定下，策略参数在优化器步之前保持不变，因此 $\theta_{upd}=\theta_{roll}$，$\ell^{upd}_{i,t}$ 与 $\ell^{roll}_{i,t}$ 数值一致，重计算在数学上是**冗余**的（论文用式 (5) 证明 $\nabla_\theta L_{clip} = -\sum_i\sum_{t\in S} A_i \nabla_\theta \ell^{upd}_{i,t}$）。
- **为什么冗余却仍被保留**：终端优势 $A_i$ 只有在整条轨迹采样、解码、打分、组内归一化之后才可得；若在 rollout 期间就保留所有选定时间步的计算图与激活，显存会随选定时间步数近似线性增长，代价高昂。因此这不是单纯工程疏忽，而是显存约束下的权衡。
- **论文贡献定位**：提出 **LeanGRPO**——一个**保持原优化目标不变**的系统级执行框架，通过重构数据并行布局 + 两种免重算调度，消除更新阶段的冗余重计算。作者还通过代码审计指出，32 个公开实现中有 23 个（71.9%）存在该冗余重计算，其中 22 个（95.7%）满足图共存（graph-colocated）条件。

## 二、方法论

### 2.1 核心思想

让 rollout 阶段直接以梯度跟踪方式评估选定时间步，从而在更新阶段**复用 rollout 产生的可微信息**，而非重新前向。为控制显存，配合两点设计：(1) 重构数据并行布局；(2) 两种互补的图/梯度消费调度。

### 2.2 共享提示词数据并行布局（Shared-Prompt）

- 传统 DP 布局：每张 GPU 处理不同 prompt 并在本地生成 M 个样本，需为每个 prompt 保留 M 个样本的图/激活或临时梯度。
- LeanGRPO 布局：**所有 GPU 处理同一 prompt，各自独立生成不同样本**。当 $Q=M/R\ge1$（R 为 rank 数），每 rank 只需保留 Q 个样本，即传统布局的 $1/R$。
- 一个 prompt 的全部生成完成后，跨 rank **all-gather 奖励**形成完整 prompt 组并计算优势；**每完成一个 prompt 组即立即训练**，避免多组累积的显存压力。
- 当 $Q<1$、$P=R/M$ 时，将 worker 划分为 P 组、每组 M 个 rank：组内生成同 prompt 的不同样本，不同组并行处理不同 prompt。
- 附录 A 证明该重排与原生 DP **梯度等价**（仅改变样本分配位置，不改变优化项集合）。

### 2.3 LeanGRPO-Retain（保留图，后向复用）

- 对每个选定时间步 $t\in S$ 执行带梯度的去噪前向，保留可微对数概率 $\ell^{grad\text{-}roll}_{b,m,t}$、计算图与保存的激活。
- 轨迹完成后 all-gather 奖励得到 $A_{b,m}$，直接用保留的图反向传播：
  $G^{retain}_{b,m} = -A_{b,m}\sum_{t\in S}\nabla_\theta \ell^{grad\text{-}roll}_{b,m,t} = G^{native}_i$（式 6）。
- 优点：调度简单；缺点：激活显存随 $|S|$ 近似线性增长，适合小时间步比例或中等分辨率任务。

### 2.4 LeanGRPO-Reweight（临时反向 + 延迟校正）

- **流程（Algorithm 1）**：对每个选定时间步，用**单位临时优势**立即反向 $L^{prov}_{i,t}=-\ell^{grad\text{-}roll}_{i,t}$，得到 $g^{prov}_{i,t}=-\nabla_\theta \ell^{grad\text{-}roll}_{i,t}$，随即**消费该步计算图并释放激活**，并 detach 潜变量以阻断跨步依赖。
- 同一轨迹所有选定步共享同一优势 $A_i$，故可先累加临时梯度 $G^{prov}_i=\sum_t g^{prov}_{i,t}$，待优势可得后整体校正：$G^{corr}_i = A_i G^{prov}_i = G^{native}_i$（式 7）。
- **校正必须先于分布式同步**（关键实现细节）：若先用 FSDP reduce-scatter 混合临时梯度，则只保留 $G^{mix}_b=\sum_m G^{prov}_{b,m}$，由于各样本优势 $A_{b,m}$ 不同，任何公共标量 $\alpha$ 都无法恢复 $\sum_m A_{b,m}G^{prov}_{b,m}$（式 8）。因此临时反向期间禁用同步，校正后再做**单次 reduce-scatter**。
- 附录 C 进一步给出**非可辨识性证明**：给定 $(G^{mix}_b, A_b)$，存在构造 $J'_b = J_b + uh^\top$ 使混合梯度相同但正确加权梯度不同，故任何后验标量/逐元素向量/非线性函数都无法一般性恢复精确梯度。
- 优点：显存与 $|S|$ 无关，仅需每 rank 保留一份完整临时梯度；适合大张量视频训练、LoRA 等场景。缺点：需要在校正后一次性同步。

### 2.5 与激活检查点的区分（附录 D）

- 论文区分两类重计算：(i) **更新阶段转移重前向**（LeanGRPO 消除的目标）；(ii) **激活检查点（activation checkpointing）**在反向内部对已启梯度的前向块的重算（LeanGRPO 保留）。"recompute-free" 特指前者。

## 六、主要结论与发现

1. **重计算是扩散 RL 的主要系统瓶颈**：在同策略、同后端、单次更新下数学冗余，但为恢复被丢弃的梯度路径而被迫保留。
2. **LeanGRPO 可保持原优化目标**：在精确算术下与 Native 梯度等价；Retain 在受控固定轨迹下**逐位一致**（cosine 1.000000，RelL2 0.00%），Reweight 梯度 cosine 0.999802、相对 $\ell_2$ 误差 1.99%（端到端单更新下 Retain/Reweight 的 $\Delta\theta$ cosine 分别约 0.9996/0.9985）。
3. **端到端加速最高 1.83×**：BF16 Full 下 Reweight 1.44×–1.81×、Retain 1.18×–1.29×；LoRA 下两者接近（约 1.26×–1.47×）；跨模型规模 1.22×–1.49×；FlowGRPO-Fast / MixGRPO-Flash / FlowGRPO(SD3.5) 上 Reweight 分别达 1.25×–1.67×、1.22×–1.47×、1.43×–1.83×。
4. **加速随时间步比例上升而增大**（更新阶段占比与重计算占比同步上升）。
5. **步时分解**：BF16 Full 下 Native 重计算耗时 402.45 s，Retain 消除之（999.16 vs 989.44 s）；Reweight 还合并同步，训练降至 535.15 s（同步 30.33 s），端到端 1.81×。
6. **收敛与奖励趋势保持**：两个变体均维持与 Native 相当的奖励提升趋势，并在相同训练时间内取得更高奖励。
7. **显存权衡决定适用场景**：Retain 常驻显存随 $|S|$ 近似线性增长（图像小张量、micro-batch≥2 时在 80 步后 OOM；视频大张量下第 6 个选定步 OOM），但低于优化器阶段峰值；Reweight 每 rank 增加一份完整梯度、与 $|S|$ 无关，适合大张量视频；对比实验表明单纯增大 Native micro-batch 仅得 1.03× 加速，说明 Reweight 的收益并非仅来自更多显存占用。
8. **适用性审计**：32 个满足标准的实现中 23 个（71.9%）存在目标重计算，其中 22 个（95.7%）图共存，可支持 LeanGRPO 的首次同策略更新；1 个（B2-DiffuRL）因采样/训练分属不同进程需重构。
9. **边界条件**：跨后端会破坏图共存；同一 rollout 的多次优化器更新在首次之后属于 off-policy，需按当前策略重计算（LeanGRPO 可作为混合调度，仅消除首次更新）。
